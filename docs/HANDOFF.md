## 3. 아직 확인되지 않은 것 (실제 PC·폰에서 필요)
- 전용 창: 윈도우 실물에서 열기와 열린 창 앞으로 가져오기 (`window.py` 의 SetForegroundWindow).
- 자동 AI 요약: 실제 LM Studio 속도와 품질, 처음 켠 날 대량 요약 (`ai.py`).
- 텔레그램: 날짜 달력(결석계·조퇴·외출), 학부모 확인 흐름, 중복 신청 경고, 업데이트 단추와 다시 켜짐, 명령 판별.
- 주간 계획: 학사일정·여러 학년 시간표로 수업 없는 날 판정, 1주/2주 기본값.
- 나이스: 실제 화면의 칸 찾기, 이름표 검사(근사치), 체크박스, 탭 전환 시 확인 창 흐름. 확장 프로그램 `neis.js`·`neisfill.py`.
- 확장 프로그램 버전 0.3.x 는 선생님 PC 에서 ↻ 로 다시 불러와야 적용됨.
- 에듀파인 공문 본문은 그림(OZ 뷰어)이라 글을 못 읽음. 공문은 기존 '에듀파인 공문 저장 폴더' 수집을 씀.

## 4. 작업 방법
- 브랜치: `claude/...` 등 짧은 이름. 같은 브랜치를 두 세션이 동시에 고치지 않는다.
- 시작할 때 `git fetch origin main` 과 `git status`. 모르는 미커밋 변경은 지우지 말고 출처를 확인.
- 시험: `python -m unittest discover -s tests -t .` 와 `node --test tests/pass-codec.test.cjs tests/browser-ai.test.cjs tests/capture-extension.test.cjs` (CI 와 같은 방식). 폴더 전체를 `node --test tests/` 로 돌리면 CI 와 다르게 실패할 수 있음.
- 버전: `desk/__init__.py` 한 줄. PR 이 겹치면 머지 직전에 큰 쪽 +1. 기록(`CHANGELOG`·`DESIGN`)은 양쪽 줄을 모두 살림.
- PR 설명: 요구사항, 바꾼 내용, 실행한 테스트, 확인하지 못한 것. 실제 PC·나이스·텔레그램에서만 알 수 있는 것은 "확인하지 못한 것"에 씀.
- 개인 정보가 든 실제 자료는 개발 폴더에 가져오지 않는다. 가짜 자료로 시험.
- 텔레그램 봇 토큰은 개발 폴더에 넣지 않는다 (같은 봇을 두 곳에서 켜면 Conflict).

## 5. 최근 무결성 점검 (2026-11-03)
- `desk/db.py`: 같은 내용이 동시에 들어올 때 중복 확인과 저장을 한 트랜잭션으로 처리하고, 실패 시 항목·일정을 함께 되돌립니다. 일정 후보를 다시 저장할 때도 기존 후보를 실패로 잃지 않게 했습니다. 학생 명단 전체 교체도 저장 실패 시 기존 명단을 보존합니다. 기록 저장과 최근 500개 정리는 한 트랜잭션으로 묶었습니다.
- `desk/collect.py`: 다른 DB 연결이 동시에 같은 자료를 먼저 저장한 경우, 뒤늦게 중복으로 판정된 수집을 정상적인 중복으로 처리합니다.
- 회귀 시험: 별도 DB 연결 동시 중복, 항목/일정 저장 실패, 명단 교체 실패, 기존 DB 마이그레이션과 로그 보관을 확인합니다.
- 확인: `py -3.13 -X utf8 -m unittest discover -s tests -t .` — 327개 통과. `node --test tests/pass-codec.test.cjs tests/browser-ai.test.cjs tests/capture-extension.test.cjs` — 14개 통과. 전체 Python 시험에서 기존 DB·소켓 관련 `ResourceWarning`이 보였지만 시험 실패는 없었습니다.
- 인쇄 대기열·업데이트 실패 시 데이터 폴더 보존·백그라운드 잠금과 종료 경로를 코드와 시험으로 점검했습니다. 현재 확인한 경로에서는 추가 수정할 문제가 나오지 않았습니다. 단, 이 작업 환경에서 실제 Windows ZIP 업데이트·기본 프린터 동작은 실행 확인하지 않았습니다.
- 로그 성능 비교(1000회, 3회): 변경 전 약 7.1초, 변경 후 약 5.0초였습니다. 시험 자료 기준 측정이며 실제 사용 PC 성능을 보장하지 않습니다.
